# AgriVision: Supabase Storage Analysis & Migration Plan

## 1. Executive Summary

In AgriVision's current architecture, persistent data is stored across SQLite databases (`data/products.db` and `data/rentals.db`), while file, media, and binary assets are either **processed ephemerally in-memory** or stored as **local static files on disk**.

The current `utils/database.py` contains no file-storage system. This document catalogs all existing file and image handling across the codebase, identifying the exact modules and functions that produce or process them, and outlines the target Supabase Storage bucket structure for when file persistence is migrated.

---

## 2. File & Image Assets Discovered

### A. Ephemeral / In-Memory Files (API Payloads)

| Asset Type | Current Handler / Module | Current Behavior | Supabase Storage Opportunity |
| :--- | :--- | :--- | :--- |
| **Plant Leaf Photos** (Crop Diagnosis) | `backend/main.py` (`_read_upload`, `_validated_image`, `/api/crop/diagnose`) & `frontend/src/pages/CropDoctor.tsx` | Uploaded via HTTP multipart `UploadFile`, parsed into a PIL Image in RAM, evaluated by `crop_doctor.py`. **Never written to disk.** | Store in `crop-diagnoses` bucket to build a persistent diagnosis history for farmers. |
| **Grad-CAM Heatmaps & Overlays** | `backend/main.py` (`/api/crop/gradcam`) & `modules/crop_doctor.py` (`gradcam_for_image`) | Generated dynamically as PIL Images, converted to PNG in an in-memory `io.BytesIO` buffer, and returned as base64 strings. | Store in `gradcam-heatmaps` bucket and return public/signed URLs instead of large base64 JSON payloads. |
| **Product QR Scans** | `backend/main.py` (`/api/products/verify-qr`) & `modules/product_verifier.py` (`decode_qr_from_image`) | Uploaded via HTTP multipart, decoded in RAM via OpenCV `QRCodeDetector`. Discarded after verification. | Store in `product-scans` bucket for audit logs of suspected counterfeit chemicals. |

### C. Future Equipment Rental Marketplace Media

In the current schema:
- The `machines` table in `data/rentals.db` contains text fields, rates, and availability, but **no image URL column**.
- In production, equipment owners need to upload photos of tractors, harvesters, and implements.
- Recommended bucket: `machine-photos` (Public read, authenticated write).

## 3. Recommended Supabase Storage Buckets

When file storage is enabled, create the following buckets in the Supabase Dashboard:

| Bucket Name | Public Access | Max File Size | Allowed MIME Types | Intended Usage |
| :--- | :---: | :---: | :---: | :--- |
| `crop-diagnoses` | Private | 8 MiB | `image/jpeg`, `image/png`, `image/webp` | Farmer-submitted crop leaf photos for diagnosis history. |
| `gradcam-heatmaps` | Public | 5 MiB | `image/png`, `image/webp` | Generated visual disease localization overlays. |
| `machine-photos` | Public | 10 MiB | `image/jpeg`, `image/png`, `image/webp` | Equipment rental listing photos uploaded by owners. |
| `product-scans` | Private | 8 MiB | `image/jpeg`, `image/png` | Counterfeit verification scan audit logs. |
| `sample-images` | Public | 5 MiB | `image/jpeg`, `image/png` | Demo UI images and educational sample library. |

---

## 4. Bucket Security & Access Policies (RLS)

### `crop-diagnoses` (Private)
- **Upload:** Only authenticated users can upload to their own user folder (`crop-diagnoses/{user_id}/*`).
- **Read:** Only the owner user or an admin can read their uploaded photos via signed URLs.

### `machine-photos` (Public)
- **Upload:** Only authenticated users with `role = 'owner'` can upload to `machine-photos/{owner_id}/*`.
- **Read:** Publicly readable by anyone browsing the rental marketplace.
- **Delete:** Only the owner who uploaded the photo can delete it.

---

## 5. Implementation Roadmap (Post-Migration Phase)

1. **Storage Utility Module:**
   Create `backend/storage.py` using `supabase.storage.from_('<bucket>').upload(...)`.
2. **Database Schema Update:**
   Add `image_url TEXT` to `machines` table in PostgreSQL.
3. **Endpoint Enhancements:**
   - Update `POST /api/rental/machines` to accept an optional image upload or image URL.
   - Update `POST /api/crop/diagnose` to optionally persist the incoming image to `crop-diagnoses` if the user is authenticated.
